# CLAUDE.md

Conclave for iPhone: the native iPhone and iPad app for Conclave (github.com/liehrdot/Conclave),
in Swift and SwiftUI. Public repo. It talks to the same sync server (or Conclave Cloud) as Conclave's
phone web app, through the same API, and never needs a server change of its own. The web app stays;
a Kotlin app for Android follows later on the same contract. Plan:
https://claude.ai/artifact/G6e75YM2qNj15gbN9Lq4YY

Claude writes the code, Flo reviews every PR and wants to learn from it: keep PRs small and explain
the why in the description. Everything is English: UI text, code, comments, docs (the web app
stays German).

## Commands

```bash
swift test --package-path Packages/ConclaveCore   # core tests, also on Linux, offline
xcodegen generate                                  # Conclave.xcodeproj from project.yml (Mac only)
```

Nobody here has a Mac: the app is built in GitHub Actions (`.github/workflows/ci.yml`), which also
keeps the unsigned `Conclave.ipa` as the run's artifact. Its `screenshots` job (only when started by hand: Actions › CI › Run workflow; Flo tests on the iPhone) runs `scripts/screenshots.sh`: the app in the
simulator, iPhone and iPad, light and dark, as the run's `screenshots` artifact (the `icon` job, `scripts/icon.sh`, runs when `App/AppIcon.icon` or the script changed, or by hand); the app opens the screen named
in the environment variable `CONCLAVE_SCREEN` (add new ones to `SCREENS` in the script). `docs/sideload.md` says how it gets onto a phone.
What runs when: a `changes` job (`git diff` against the PR's base) lets the Mac jobs skip pull requests that
can't affect them: `ios` and CodeQL `swift` only for `App/`, `Packages/`, `project.yml` or their workflow, CodeQL `actions`
only for `.github/`; pushes to `main`, the weekly CodeQL run and runs by hand always do everything. Use a job-level `if:`,
never a workflow `paths:` filter (a required check that never starts blocks the merge; a skipped one passes). A new push
to a PR cancels its older CI run. Tests, SonarQube and the `claude` review run on every PR.

## Layout

- `project.yml`: the Xcode project, generated by XcodeGen; `Conclave.xcodeproj` and `App/Info.plist`
  are not in git. iOS 26 and Swift 6 (strict concurrency).
- `App/`: the SwiftUI app target. Screens only, kept thin.
- `Packages/ConclaveCore/`: everything without a screen (server calls, outbox, the rules of the
  phone's operations, scanner rules), with Swift Testing tests next to it. `Pairing` parses pairing
  links and codes, `ETag` reads the read model's tag behind Caddy's suffix.
  `JSONValue` keeps any JSON as it came (the read model has keys the app doesn't model).
  `Server` is the phone API (claim, read model with `If-None-Match`, status, sign off) over a `Transport`
  (`URLSession.conclave()`: no URL cache, no cookies; tests use `FakeTransport`), errors as `ServerError`.
  `Connection.pair`/`signOff` = parse, claim, save in a `DeviceStore` (the app's is `KeychainDeviceStore`), with
  the English sentences the app shows (`Connection.message(for:)`).
  `Connection.refresh` fetches into a `ReadModelCache` and forgets the device and its decks when the PC signed it off (401).
  `ReadModel` = the typed read model (decks, opponents, games, `Options`); `shown…` prefer the server's
  English `*_en` fields and fall back to German. `ReadModelCache` keeps the raw JSON + ETag on disk and
  `refresh(from:)` sends `If-None-Match`. `CollectionEntry` = the read model's `collection`; `ReadModel.copies(of:in:)`
  = the copies placed in a deck (real and foil first, capped at the deck's count, like the PC's `_deck_value()`),
  `imageURL()` = that printing's picture from its Scryfall id.
  Cards: the read model has only names, so `Scryfall` (an actor: `/cards/collection` in batches of 75 asked by the
  front face, requests ≥ 100 ms apart, `Accept` + `User-Agent`) looks them up into `Card` (faces, Oracle text,
  default printing's pictures); `CardLibrary` keeps them on disk by name (`prefetch` when a deck opens, `clear()` on
  sign-out; `remember` keeps a search's English cards). Search (`scry.js` `searchQuery()`/`searchCards()`): `Scryfall.search(query, page:)` =
  one `SearchPage` (`order=edhrec`, 404 = no hits, 400 = `CardError.badQuery`, "+" sent encoded), `find(name:)` = `NameHit`s for a typed
  English or German name (multilingual search + autocomplete, `exactFirst`). `CardFilter` = the Cards tab's filters (a Tagger `role`, colours,
  types) as one Scryfall query; `compose()` mirrors the server's `cardsearch.compose()`. `Describe.swift`: `Server.describe` (`POST /api/app/cards/describe` › `DescribeAnswer`),
  `aiSettings()`/`setAI(key:model:)` (`GET|PUT /api/app/ai`, `AISettings` never holds the key), `ServerError.needsSetup` (409). `Outbox` (an actor, kept in a file) = the phone's changes on their way to the server, like the web app's
  `data.js`: `add`, `flush(to:)` (`POST /api/app/ops`, batches of 50, backoff 5 s → 5 min, `retry` stays, refused → `failed`),
  `confirm(etag:)` drops sent ops once a read model's seq covers their ack, `undo` (drop if unsent, else `inverse` = `INVERSE`).
  `Optimistic.apply(ops, to:)` = the read model as it will look once the server has the outbox's ops (`data.js` `apply()` +
  `recompute()`, on the raw JSON): games, opponent decks and the collection so far (`collection.add`/`update` follow
  `appops._collection_add`/`_collection_update`, merging entries by `appops._coll_key`), checked against every matching `ops.json` case.
  `CollectionEdit.swift`: `ReadModel.collectionGroups(matching:filter:)` (one group per card; the search looks at name, set code
  and place), `collectionTotals`, `placeName(of:)`, `knownPlaces` (`collection.js`/`scan.js` `knownPlaces()`), and
  `CollectionEdit` = the Collection tab's `collection.update` payloads (copies, proxy, foil, `move` to a deck or place, `remove`
  with `restore` for "Undo"), like the PWA's `entrySheet()` and `placePage()`.
  `GameDraft` = the "Log a Game" form's state and rules (`forms.js` game sheet: rematch within 8 h, `setResult`, `setPlace` fills
  the last place and decides win/loss, `payload` = `game.add`). `ReadModelCache.loadJSON()` = the raw saved copy for `Optimistic`.
  `PendingOp.summary(in:)` (`OpSummary`) = a change in a few words ("Loss with Meren") for the toast and the refused list.
  `OpponentEdit` = the opponent screen's changes as payloads (`update` sends only changed name/player/bracket with `prev`,
  `toggle` a tag chip, `note`), like the PWA's `editOpponentSheet()` and its tag chips / note form.
  `Mana.pieces` splits `{2}{B}`/`{T}` text into symbols (`Kind`, `spoken` for VoiceOver).
- App: `AppModel` (paired device, `library` = the read model from `ReadModelCache` with the outbox's `ops` applied
  (`Optimistic`), `save(type, payload)` = queue + show + send (sets `saved` for the toast), `undo(op)` = `Outbox.undo` + send the inverse,
  `dismiss(op)` drops a refused op, `waiting`/`refused` for the status line, `send()` flushes and refreshes after a batch, `refresh()` on opening, on
  return and every minute via `Connection.refresh`; a 401 leads back to the welcome screen), `RootView` (welcome or
  `MainView`), `WelcomeView` → `ScanView` (VisionKit QR) or `EnterCodeView`; `MainView` = tabs Decks (`DecksView` →
  `DeckView` → `Rule0View` sheet, `LogGameView` sheet ("Log a Game": result as a segmented control, opponents via `OpponentPicker`,
  places, "More Details"), `CardSheet` per card: the own copy's printing (foil sheen, several copies to pick; from the Collection tab all the person's copies, `inDeck: false`),
  else Scryfall's, 3D turn for double-faced cards, `ManaText` rules text) and Opponents (`OpponentsView` → `OpponentView`: tag chips "What It Does" save on a tap, "Add Note" › `AddNoteView`,
  "Edit" › `EditOpponentView` (name, player, bracket; not the commander yet)), Collection (`CollectionView`: totals as
  `StatPill`s, an All/Original/Proxy/Foil filter kept in `AppStorage` `collectionFilter`, `.searchable`, one row per card with
  its printing's picture › `CollectionCardView`: a section per entry with copies (a `Stepper` that saves once the taps pause
  for 700 ms), Proxy and Foil toggles, Place › `PlacePicker`, and "Remove from Collection" without a question, since the toast
  has "Undo") and the search tab Cards (`CardsView`, `Tab(role: .search)`:
  `.searchable`, `find(name:)` 300 ms after typing pauses, rows with `CardArt`, the last 12 opened in `AppStorage` `recentCards`, tap › `CardSheet`; "Filters" in the top bar › `FilterSheet` (with a filter the name search is one paged `Scryfall.search`, without a name
  the most played cards that fit; `FilterSummary` row above the results); a Name | Describe switch in the top bar: `DescribeSearch` (`App/DescribeView.swift`) = description + colour/type chips ›
  `Server.describe` › `Scryfall.search` with "Show More", the broader query when nothing matched, the query shown; 409 › `AISetupView` (also in
  Settings › "Search by Description": key as `SecureField`, model picker, sends only what changed); not in the demo); the outbox's status (`App/OutboxStatus.swift`): on the iPhone from iOS 26.1 the
  tab bar's bottom accessory (`.outboxAccessory()` on the `TabView`, `tabViewBottomAccessory(isEnabled:)`, shown only while
  `hasOutboxStatus`, short text when `.inline`), else (iPad, iOS 26.0) a glass pill above the tab bar (`.outboxStatus()` on the
  Decks and Opponents tabs) = the "… saved" toast with "Undo" for 6 s, else "N changes weren't saved" › `RefusedChanges` sheet, else a quiet
  "N changes waiting to be sent" that sends on a tap; never "waiting" in the demo), `SettingsView` from the gear (a short list like the iPhone's Settings: Connection row › `ConnectionView` (server, this
  device, last update, "Your PCs" from `AppModel.loadStatus()` = `GET /api/app/status`, `ServerStatus.PC.lastSeen(now:)` on the
  server's clock), "Open the Web App", About Conclave › `AboutView` (version, source, Scryfall, Mana, Fan Content Policy), Sign Out).
  Screens for screenshots: `welcome`, `code`, `scan` (the simulator has no camera: "No Camera"), `signed-off`, and
  with the made-up account `App/Resources/demo.json` (written by `scripts/make_demo.py` from the web app's demo):
  `decks`, `deck`, `rule0`, `log-game` (a filled-in loss), `saved` (the deck screen with the toast after `screenshotGame`), `card` (the foil Birds of Paradise placed in the first deck; picture from Scryfall),
  `opponents`, `opponent`, `edit-opponent`, `collection`, `collection-card` (the foil Birds of Paradise), `cards` (a search for "Sol"), `filters` (green ramp, no name), `describe` (a filled-in description), `settings` (the demo's settings) (`AppModel.launch()`, no Keychain).
  Demo mode: "No PC at hand? Try the Demo" on the welcome screen = `AppModel.startDemo()`: the same `demo.json` with
  the stand-in `Device.demo` (never saved, no token, `refresh()` skips it), kept across launches in UserDefaults
  `demo` like the PWA's `amtisch.mode`; "Demo" in the top bar (`DemoBadge`) and Settings › "Leave Demo".
  Mana symbols: `ManaText` draws `ManaGlyphs` (circles + the Mana font's glyphs, SVGs in `Assets.xcassets/Mana`,
  OFL licence in `App/Resources/Mana-LICENSE.txt`) inline in a `Text`. `CardImages` caches card pictures on disk
  (`returnCacheDataElseLoad`, 300 MB in Caches).
  Look (`App/Look.swift`): the commander's blurred art behind the screens (`ArtBackdrop`, Flo's pick in draft PR #14), with
  the content on standard materials (`.regularMaterial`) and Liquid Glass only on the floating layer (bars, sheets, the outbox
  pill, controls over the camera), as Apple's guidelines ask (Flo's decision 2026-10-26; the doc with the sources:
  https://claude.ai/artifact/KBeA2toTQ6YPCAS32i1rpW). The Decks tab is a `TileGrid` of `ArtTile`s (the commander's art in a
  circle, on the material, the first deck's art blurred behind them); a deck's screen is an `artList(over:)` with a big header
  (name, commanders, chips, `StatPill`s, one prominent "Log a Game" + glass Rule 0 button), `SectionTitle` headers and
  `materialRow()` rows with a `CardArt` thumbnail.
  `CardArt` = a card's art crop from `CardLibrary` + `CardImages`; the Decks tab prefetches all commanders at once.
  Shared: `TileGrid` (tiles over a backdrop, columns on the iPad) + `ArtTile` for the Decks
  and Opponents tabs; the opponent screen, Rule 0 and the card sheet sit over their commander's or card's art too.
  Accessibility settings (HIG, Typography and Accessibility): names wrap instead of being cut off, `AdaptiveStack` turns
  a row (header chips, `StatPill`s, the deck's two buttons, a tile's facts, a place row's numbers) into a column at the
  accessibility text sizes, the outbox accessory caps its text at xxLarge like the tab bar, `ArtBackdrop` covers the art
  more with Reduce Transparency or Increase Contrast, and with Reduce Motion a card's sides cross-fade instead of turning.
  Settings stays a plain iOS form on purpose (it's a utility sheet, like the iPhone's own Settings).
  Colours (HIG, Color): `AccentColor` = dark green in light mode, neon in dark, each with an Increase Contrast variant; it marks
  what you can tap (text, icons, picked choices) and is the background of the one prominent button per screen
  (`.glassProminent`/`.borderedProminent`), whose label is `OnAccent` (white on the dark green, black on the neon). Every
  custom colour has light, dark and high-contrast values; text colours reach 4.5:1. `Chip` = a label on the material: a
  bracket's dot goes blue › teal › yellow › orange › red in system colours (`Chip.tone`; never green, that's the accent), a
  problem gets a red sign; the words always say it too. Mana pips keep Magic's own colours (content, like the art).
- `Packages/ConclaveCore/Tests/ConclaveCoreTests/Resources/ops.json`: Conclave's shared operation cases
  (`docs/app-api.md` there), copied at the commit in `ops.rev` by `scripts/update_api_cases.sh <full hash>`.
  Re-run it when Conclave's `appops.py` changes; the core's operation code must pass every case.

## Rules

- The sync server's API is the contract (`/api/pair/claim`, `/api/app/data|status|ops`, …). What the
  web app's `data.js` and the server's `appops.py` do, the core does the same way; say which function
  it mirrors in the doc comment.
- Every logic change gets a test in ConclaveCore. CI runs the tests and the build.
- No AI features (Flo's rule for Conclave). The one exception is the existing „Beschreiben“ card
  search through the sync server. Apple's Vision text recognition for the scanner is fine: it reads
  text on the phone, like Tesseract does in the web app.
- The macOS jobs are pinned to `macos-26` and Xcode 26.6 (`XCODE` in `ci.yml` and `codeql.yml`): CodeQL can't read Swift
  built with Xcode 27, and Xcode 27 changes the app's look (iOS 27 glass). Move to it only on purpose, in both files.
- No third-party UI libraries; add a dependency only where Apple has nothing.
- Follow Apple's Human Interface Guidelines and read the page before deciding (the JSON behind every page:
  `https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<page>.json`). No `.glassEffect` on
  content (tiles, rows, pills, panels): standard materials there; colour goes on the background of the one main button.
